# Report contract

Produce a readable summary with links to a machine-readable case matrix and retained artifacts. Reuse the runner's format where it preserves the same semantics. Use stable scenario IDs for comparisons. Name the builds and conditions compared, the obligations satisfied, and what remains open.

- **Run identity.** Record the scope and bundle/check revisions, source and runnable build identities, fixture and effective condition identities, exact command, run IDs, and environment classification. Capture relevant setup, test execution, cleanup and reporting exit states separately. Pin the baseline and candidate independently.
- **Case evidence.** Record expected/actual outcomes at the intended assertion, observed side effects and correlation, evidence references and the precise failure stage. Retain per-suite discovery and observed outcomes. Distinguish discovered but skipped, filtered out, never run and blocked by infrastructure. Keep a baseline's missed controlled fault visible as a baseline coverage gap.
- **Verdict.** Use `verified` for applicable observations that meet the obligation, `divergent` for an observed mismatch, and `unverified` for absent or unsuitable proof. An expected test failure only verifies fault detection if it reached the intended assertion and the defect control worked. A pair of equal outcomes alone establishes no coverage. Report approved changes separately from observed parity.
- **Report and publication.** When in scope, inspect the actual case and failed step in raw and rendered results. Verify links, attachment bytes, fresh-run membership, permitted content and exit propagation after failure. Normalize equivalent representations only where the mapping preserves identity, status and meaning. Exercise publication with an authorized isolated receiver and inspect what arrived. Distinguish local generation, isolated CI stages and hosted workflow or deployment. Record the actual stage and show any configured-only behavior.
- **Effort and recovery.** Record elapsed setup, execution, cleanup and publishing phases. Separate agent or implementation time from operator interventions and review where captured. State what timing or evidence is unavailable. Link original and later attempts with their reason and revisions. Keep retained details accessible and return only decision-relevant facts inline.
- **Completion.** Use deterministic checks to derive pass/fail. Return a nonzero verification exit for a divergence against the applicable acceptance criteria, a blocking unverified obligation, or required cleanup, report or publication failure. Preserve native runner and publisher exits in the receipt. Report only the verified extent, such as a same-machine replay or clean-worker provisioning.
